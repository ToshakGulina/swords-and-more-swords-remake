# Сверка с оригиналом 2.8.8 — сводный отчёт

Отчёт о статической сверке ремейка (3.0.4, `@minecraft/server` 2.6.0, `min_engine_version` 1.26.20) с эталоном **Swords and More Swords 2.8.8**. Сверка велась **построчно, файл за файлом**, по всем 403 файлам `.mcaddon` оригинала.

> **Границы отчёта.** Здесь зафиксировано только то, что проверяется кодом и схемами. Игровое поведение — доставка событий движком, дропы после взрыва, ощущения от боя — этим отчётом **не подтверждается**. Ведомость для двух очных проходов остаётся в `TESTING.md` и не считается выполненной.

## 1. Методика

| Шаг | Чем делался |
|---|---|
| Попарное сравнение всех 403 файлов 2.8.8 с `packs/` | `tools/parity_report.mjs` (JSONC через `jsonc-parser` + побайтовое сравнение) |
| Отсев шума миграции 1.16 → 1.26 | нормализация ключей, сведение `damage: N` ↔ `{min,max}`, сравнение по «игровым» компонентам |
| Проверка соответствия схеме 1.26.60 | `npm run validate` (Blockception) |
| Регрессии | `npm test` — 33 набора `tools/test_*.mjs` |

Главный принцип разбора: **расхождение по умолчанию считается дефектом ремейка**, а не «намеренным отличием». Отклонение от 2.8.8 остаётся только если оно вынуждено (удалённые или переименованные в 1.26 данные) либо прямо согласовано.

Пример распределения: 167 файлов помечены как «changed», но это почти всегда структурная миграция (`category` → `menu_category`, `icon.texture` → `icon.textures`, `foil` → `glint`, `weapon` → `effect:sword`, `block_light_emission` → `light_emission`). Дефекты ищутся только в значениях, которые движок реально читает.

## 2. Найденные и исправленные дефекты

Все пункты ниже исправлены в ветке, каждый закрыт коммитом и, где возможно, тестом.

### 2.1 Снаряды наносили нулевой урон

Самое серьёзное: сборка копировала ванильные сущности 1.26, где урон стрелы и малого фаербола берётся **от стрелка** (`damage: {min: 0, max: 0}`). Скриптовый `spawnEntity` стрелка не имеет — удары не наносили урона вообще.

| Снаряд | 2.8.8 | Было в ремейке |
|---|---|---|
| Стрела (Bone Sword) | урон 1–4, `power` 1.6 | `{min: 0, max: 0}` |
| Малый фаербол (Blaze) | урон 5, `power` 1.3 | 0 урона |
| Фаербол гаста | поджигает, урон только взрывом; `catch_fire: true`, хитбокс 0.31 | прямой урон 6, `catch_fire: false`, хитбокс 1.0 |
| Черепа Wither | `power` 1.2 / 0.6, летят ровно | 1.8 / 1.8 |
| Пуля Шалкера | Левитация **II** (`amplifier: 1`) | Левитация I |
| Снаряд молнии | таймер 0.1 с, `looping` | 1.2 с, одноразовый |
| Трейсер Звезды | таймер 0.1 с, `looping` | 1.0 с |
| Снаряд Wither-эффекта | таймер 0.1 с, **без** `remove_on_hit` | 0.6 с + `remove_on_hit` |

Коммиты `f8b7220`, `e20d222`, `75e8f9a`. Тест: `tools/test_projectile_parity.mjs`.

### 2.2 Изумрудный меч был недоступен

В таблице торговли оружейника было **6 тиров**, а у жителя только 5 уровней — шестой недостижим, и сделка на изумрудный меч лежала именно там. В 2.8.8 сделка в пятом тире. Перенесена в существующий пятый тир; числа сделки не менялись (32 изумрудных блока, `max_uses 2`, зачарование 5–60). В сборку добавлена защита, падающая при попытке сделать больше пяти тиров.

Коммит `bb726b6`. Тест: `tools/test_sword_acquisition.mjs`.

### 2.6 Лут и прочее

- **Кувшинка**: в 2.8.8 лежит в *сокровищах* рыбалки с весом 5. Ремейк убрал её оттуда и добавил в *мусор* с весом 17 — редкое сокровище стало самым частым мусором. Возвращено (коммит `e64cfd8`, тест `tools/test_fishing_loot.mjs`).
- **Огненный меч в дожде**: ровно 5 с → случайные 5–6 с, как одноразовый `randomInterval`-таймер оригинала (коммит `aa96902`).
- **Подсказка выхода из панциря шалкера**: была инструкцией, в 2.8.8 — название транспорта (коммит `52478ae`).

## 3. Проверено и оставлено как есть

Эти расхождения выглядят подозрительно, но дефектами не являются. Каждое проверено по первоисточнику.

**Вынужденная миграция:**
- `deals_damage: false` → `"no"`, `minecraft:weapon`/`on_use` → `effect:sword` + обработчик скрипта, события с префиксом `effect:`.
- `addrider.entity_type` → `addrider.riders[]`; `family_types: zombie` → `baby_undead` у паука (ванильное переименование).
- `minecraft:is_baby` у `living_flame` и `grows_crop` — требование 1.26 для работы `ageable`, иначе взросление не срабатывает.
- Дробный урон: `minecraft:damage` в 1.26 целочисленный, поэтому ледяной меч пишет 8, а мгновенный 0.5 наносится скриптом (итого 8.5, как в 2.8.8). То же у магмового: 7 + 0.2.
- `sponge` + `set_data: 1` — это и есть влажная губка, поэтому ванильный `wet_sponge` у древнего стража верен. `dye` + `set_data: 0` → `ink_sac`, веса сохранены.
- Устаревшая грамматика рецептов (`data: 0` в `ingredients`/`key`) отброшена.

**Переработано на скриптах с тем же поведением:**
- Эндер-кристалл (18 с перезарядки, всадник, дроп), саженец `sapling3` (мгновенное дерево), мини-крипер как отдельная сущность, 7 BP-анимаций (`climb_spider`, `ghost_sword`, `item_events`, `shulker_sword`, `wither_sword`, `wolf_sword`, `despawn`), `functions/{jungle_sword,tag_swords,tellraw1}.mcfunction` (легаси на старых id).
- Мёртвые ссылки оригинала: `loot_tables/entity/centella.json` (папка называется `entities`) — ремейк корректно указывает на `empty.json`.
- `trading/weapon_smith_trades.json` в 2.8.8 — формат до 1.11, заменён `economy_trades`.

**Обновление ванили 1.20 → 1.26** (2.8.8 содержал копии старых таблиц, поэтому они «отличаются»):
- сундуки: медные доспехи, шаблоны отделки, `resin_clump`, `goat_horn`, `village_bundle`;
- рыбалка: `clownfish`/`pufferfish` в `jungle_fish`;
- 9 отсутствующих `chests/*` структурно совпадают с ванильными, восстанавливать нечего;
- 3 PNG кнопок попиксельно идентичны (отличается только сжатие).

**Согласовано с вами:**
- `slime_king` — подключена мёртвая таблица лута (в оригинале дропа не было вовсе).
- Трейды: **вся таблица оружейника взята из 2.8.8** (см. раздел 3.5); ранее выравнивались только сделки с мечами.
- Pumpkin Sword — секретная 41-я страница памятки, последняя в списке.
- `spawn_rules`: сверено построчно с 2.8.8. Правки — только там, где оригинал
  ссылался на блоки и биомы по устаревшим именам или терял событие спавна:
  `alpha_wolf` (`grass` → `grass_block`/`podzol`/`snow_layer` + `spawn_event`
  `effect:natural_spawn`, иначе волк никогда не приходил «обычным» и не выл в
  полнолуние), `ghost` (`stone` обновлён до `stone`/`deepslate`/`tuff`, иначе
  призрак не спавнился в новых пещерах), `living_flame` (`spawns_on_surface` не
  нужен под землёй, но событие `hostile_entity` добавлено — иначе пламя выходило
  пассивным), `slime_king` (добавлен `mangrove_swamp`).

**Расширения ремейка, оставленные осознанно:** `give.mcfunction` выдаёт все 38 мечей и материалы (в 2.8.8 список был частичным); тексты `.lang` переписаны под 1.26; `item_specific_speeds` в блоках требует эксперимента и потому не влияет на игру; `render_offsets` намеренно не добавлены (ломают 3D-модели).

Сверялись не файлы целиком, а каждая команда событий: `on_use`, `weapon`, группы
`component_groups` с таймерами и датчиками. Найдено и исправлено:

| Меч / механизм | Что было в ремейке | Что в 2.8.8 |
|---|---|---|
| Blaze Sword, ПКМ | 8 настоящих `small_fireball` сразу | `blaze_sword_skill` ждёт 6 с, затем 4× `entity:fake_fireball` (`set_sound`), группа снимается через 2 с |
| Ghost Sword, ПКМ | «телепорт сквозь стены» | `shoot entity:ghost_projectile` (power 2.5, урон −1), −6 прочности |
| Ice Sword, ПКМ | одна клетка 3×3×4 на всех | 43 `fill` с размерами по существу: enderman 3 в высоту, elder guardian и ghast крупнее, слизни medium/small и лошадь вырезаются обратно, снаряды — 1 блок, другие игроки — с 3 блоков |
| Ice Sword, лёд | тает в воду | `destroy_block` = `setblock air`, из воды тоже воздух |
| Quartz Sword, удар | убивал владельца | `effect @a[r=1] instant_damage 1 99`: `@a` — только игроки, значит бьёт всех игроков в 1 блоке вокруг держателя, включая его самого, в любом режиме игры и не задевая мобов; лишний раскат грома убран |

| Clock Sword | один скачок +1000 тиков и Speed IV | 5 с `randomtickspeed 100`, `speed 1 10` всем, `time add 10` — ровно 1000 тиков, как обещает памятка |

| Ghost Sword, X-ray | делал стены прозрачными | в 2.8.8 у призрака только `movement: 0.14` |
| Ender Sword | телепорт 2–16 без звука | `spreadplayers ~ ~ 0 16` + `mob.endermen.portal` |
| Свет мечей | куб на 1 блок выше | `fill ~1 ~1 ~1 ~-1 ~-1 ~-1` центрирован на ногах |
| Ифрит, урон по цели | 14 % шар + 1 % большой | то же, но огнестойкость даётся ТОЛЬКО в выпавшей ветке (уже совпадало) |
| Фоновые звуки | `tick % 160` + бросок 0.45 | таймеры `[6,18]` (ender) и `[4,18]` (wither) без дополнительного броска |

старым движком; в 1.26.60 `spawnEntity` его отвергает. Флаг включён — так же, как
ремейк уже делает для `fireball`, `small_fireball`, `shulker_bullet` и обоих
черепов визера.

## 3.2. Проход по `entities/` и реакциям выброшенных мечей

Сверены все девять сущностей, которые 2.8.8 переопределяет поверх ванили
(`item`, `skeleton`, `wolf`, `bee`, `blaze`, `cat`, `ghast`, `lightning_bolt`,
`wither`), и поведение `entities/item.json`. Найдено и исправлено:

| Что | 2.8.8 | Было в ремейке |
|---|---|---|
| Выброшенный губчатый меч | `fill ~2 ~2 ~2 ~-2 ~-2 ~-2 sponge replace water`, затем `replace sponge` и `replace seagrass` | заменялся один блок под мечом |
| Огненный меч в воде | `fire_sword_event_2` грузит **стеклянный** меч | загружался обсидиановый |
| Огненный меч в руке | `entities/fire.json` подменяет группу: `power` 1 → **10**, поджиг при попадании | стрелял обычным медленным фаерболом |
| Меч Ифрита | дроп только из loot-таблицы (`snow_golem`, 2.5 %) | плюс дубль в скрипте — два меча с одного убийства |
| `entity:grass` | `slowness 2 15` всем мобам в 1 блоке | слоунесс отсутствовал, радиус тега 2 |
| Деспавн-группы | `minecraft:despawn` (проверяется каждый тик) | `minecraft:instant_despawn` в группе — **не работает**, сущность оставалась жить |

Последний пункт задевал 31 сущность и был невидим статически: компонент
`minecraft:instant_despawn` применяется только при создании сущности, а добавление
его группой через событие — задокументированный no-op. Из-за этого турели
Звезды, маркер `objective`, кристалл, мини-крипер и снаряды, которые должны были
убирать себя сами, оставались в мире навсегда.

Переопределения `skeleton`, `wolf`, `bee`, `blaze`, `cat`, `ghast`, `wither`,
`lightning_bolt` в ремейке заменены скриптом: их роль — реакции на смерть,
`bone_sword`-структура и `centella` из молнии. Сверено построчно, роли совпадают.

## 3.3. Панцирь шалкера и система `stop_*_event`

2.8.8 снимает эффект меча событиями `stop_<меч>_event` (их 31 в `player.json`),
которые вызывает `environment_sensor` по `has_equipment ... operator: !=`. Ремейк
заменил всю систему скриптовым сравнением меча в руке — это эквивалент, кроме
одного места: выход из Панциря шалкера. Там 2.8.8 полагается на
`stop_shulker_sword_event`, который вызывает сам панцирь
(`event entity @p[family=shulker_sword,r=6] stop_shulker_sword_event`) в своём
`minecraft:despawn`. В ремейке обработчика не было вовсе, а выход угадывался в
пассивном тике, поэтому разрушенный панцирь оставлял игрока уменьшенным и
неуязвимым. Теперь движок подписан на data-driven событие
`stop_shulker_sword_event`, а выдуманное `resistance V` во время укрытия убрано —
в 2.8.8 защиту даёт `damage_sensor` группы `shulker_hiding`.

## 3.4. Блоки, руды и снаряды

**Снаряды.** В 2.8.8 снаряд запускает событие предмета `shoot`, а `launch_power: 1`
означает «со скоростью, записанной в самой сущности». Скрипт задаёт скорость сам,
поэтому каждое число должно повторять `power` сущности. Здесь было два системных
промаха:

| Что | 2.8.8 | Было в ремейке |
|---|---|---|
| Огненный шар (Ghast-мечи) | `power` 1.6 | 1.35 и выдуманная группа `effect:player_shot` (1.8) |
| Черепа Wither | 1.2 / 0.6, группа `wither_sword` | 1.4 / 1.5 через `player_shot` |
| Пуля шалкера | 1.6 | 1.1 и `power` группы 1.8 |
| Снежок ледяного меча | 1.5, урон только по blaze (3) | 1.4 и придуманный урон 2 по всем |
| Стрела / малый фаербол | `inertia` 1, отбрасывание true / false | `inertia` 0.05, отбрасывание true / true |
| Паутина, тыква, кристалл Энда, ультра-инстинкт | 1.5 / 0.3 / 5 / 2 | 1.25 / 0.95 / 1.45 / 1.0 |
| Череп по мечу Wither | уменьшается до 0×0 и своя гравитация | группа отсутствовала |

 Группы `effect:player_shot` в 2.8.8 нет вовсе — это была выдумка ремейка, и она
разгоняла снаряды. Добавлен тест `tools/test_launch_speeds.mjs`: он читает `power`
из пакета и сверяет с каждым вызовом `shootCustomProjectile`.

**Блоки.**

| Блок | 2.8.8 | Было в ремейке |
|---|---|---|
| `lightblock` / `lightblock2` | `render_method: blend`, `explosion_resistance 999` | `alpha_test`, сопротивление 0 |
| `fake_ice` | нет `minecraft:friction` | `friction 0.02` — лёд скользил |
| `sapling3` | `geometry.null` + текстура `null`, коллизии 0 | видимый крестик саженца |
| Кварц-алмазная руда, дроп | вес 89 → 1, 10 → 1–2, 1 → 2–4 | Silk Touch и Fortune, которых в 2.8.8 нет |
| `instant_damage 1` при добыче | одно сердце | шесть сердец |

**Огненный меч в воде.** Проверено отдельно: меч в 2.8.8 действительно исчезает —
`environment_sensor` переводит игрока на `stop_fire_sword_event`, когда
`has_equipment hand != effect:fire_sword`, а сам предмет при этом не выдаётся и не
удаляется. В ремейке это делает скрипт; поведение совпадает, предмет не выпадает.
`hurt_on_condition` с `in_water_or_rain` относится к Ender-мечу и Blaze-мечу, а не
к огненному, и в ремейке заменён скриптовым уроном.

## 3.5. Торговля оружейника

Таблица `trading/economy_trades/weapon_smith_trades.json` была современной ванильной
с одной добавленной сделкой на изумрудный меч. В 2.8.8 это **своя копия стола
торговли версии 1.13**, и игрок видит именно её:

| Тир | 2.8.8 | Было в ремейке |
|---|---|---|
| 1 | 15 угля → 1 изумруд (6 исп.), 3 изумруда → железный топор (3) | 16 и 12 использований |
| 2 | 4 железа → изумруд (5), 2 изумруда → **2** зачарованных железных меча (2) | железный меч за 2 изумруда, 1 шт., 3 исп. |
| 3 | 24 кремня → изумруд (5), 36 изумрудов → колокол (2) | колокол оказался во втором тире |
| 4 | 1 алмаз → изумруд (5), 8 изумрудов → зачарованный алмазный меч (2) | 12 изумрудов, топор вместо меча |
| 5 | 12 изумрудов → зачарованный алмазный топор (2), 32 блока изумруда → изумрудный меч (2) | — |

Итог: оружейник был заметно богаче оригинала — цены ниже, износа сделок почти нет.
Теперь файл целиком копируется из 2.8.8; ключ `tiers` остаётся объектом, как того
требует движок. Тест `test_sword_acquisition.mjs` пиннит все пять тиров.

## 3.6. Что осталось отличным осознанно

Проверено и оставлено, потому что это осознанные решения (раздел 2) или
исправления явных поломок оригинала:

- `spawn_rules` — см. раздел 2 (обновлённые имена блоков, `spawn_event`, биом).
- Девять chest-таблиц (`village_armorer`, `village_butcher`, `village_fletcher`,
  `village_temple`, `village_toolsmith`, `village_blacksmith`,
  `village_two_room_house`, `stronghold_crossing`, `dispenser_trap`) в ремейке
  отсутствуют — они **побайтово равны ванили** и ни одного `effect:`-предмета не
  содержат, поэтому переопределять их нечего.
- `entities/item.json` не переносится: реакции выброшенных мечей на огонь, воду и
  дождь реализованы скриптом (`worldEvents.ts`), включая `fire_sword_event_3`
  (пять `entity:living_flame` с событием `hostile_entity` в огне).
- `entities/{bee,blaze,cat,ghast,item,lightning_bolt,skeleton,wither,wolf}.json` —
  роли перечисленных ванильных сущностей (реакции на смерть, дроп, `centella` из
  молнии) перенесены в скрипты; проверено по событиям, см. раздел 3.2.
- `Swords_R/entity/bed_sword.entity.json` — копия ванильного клиента кровати,
  ничего не меняет; `witch.v1.0.entity.json` в ремейке называется
  `witch.entity.json` с тем же идентификатором.
- `functions/` (`jungle_sword`, `tag_swords`, `tellraw1`) заменены скриптами.


## 3.7. Сценарный проход: что нашлось после сверки файлов

Построчная сверка `player.json`/`items/*.json` не ловит ошибки, которые видны
только в игре. Отдельный проход по сценариям (место, время, измерение, погода,
фаза луны, режим игры, мультиплеер, смерть/респавн/переходы) нашёл следующее.

| Сценарий | 2.8.8 | Было в ремейке |
|---|---|---|
| Оборотень в полнолуние | `complete_wolf_transformation` + `wolf_movement`: `attack 15`, семейства `wolf`/`wolf_sword`/`monster`, `movement 0.18`; здоровье остаётся 20 | 40 HP, `knockback_resistance 0.4`, `scale 1.05` — всё выдумано |
| Альфа-волк без Серебряного меча | `damage_sensor` (`hand != silver`, `is_family player`) вешает `resistance`/`regeneration` II на 1 с; второе попадание любым оружием возвращает их | регенерация начислялась скриптом каждые 10 тиков, но снималась только тегом |
| Приземление на Слизистом маунте | делает сама сущность: `damage_sensor fall` -> `fall_damage` -> `instant_damage 1 1` всем в 1 блоке (кроме `slime_sword`/`undead`) и `instant_health 3` нежити | скрипт повторял удар `applyDamage(6, entityAttack)` от имени всадника: двойной урон, нежить получала урон вместо лечения, урон мог запускать оружейные события всадника |
| Турели Звезды Нечестивого | `summon entity:nether_star ^ ^20 ^-6` — вокруг **держателя**: 20 блоков вверх, 6 назад; трассер летит с `power` группы = 5 | турели над жертвой (18 вверх, ±1.5), трассер 2.2 |
| Паутина Паучьего меча | `shoot entity:web` без звука от меча | на каждый из 40 снарядов добавлялся `mob.spider.step` |
| Свет мечей при выходе/портале | блоки `lightblock` удаляются собственным `ticking` | подтверждено: `clearTrackedLight` работает по сохранённым координатам и при выходе игрока тоже |
| Кварцевый меч в креативе | `effect @a` без исключения режима | владелец не умирал в креативе |

## 3.8. Сознательно оставленные расхождения в лутах

Ванильные таблицы (крипер, шалкер, элдер-страж, визер-скелет, красный эндермен,
слизень-король) ship'ятся как современная ваниль, а не как копии 1.13 из 2.8.8:
современные таблицы содержат новые предметы (`bogged`-пластинки, шаблон отделки
`tide`), которых в 1.13 не существовало. Скриптовые дропы (`blaze`, `skeleton`,
`witch`, `ghast`, `centella`, `bee`, `alpha_wolf`, `wither`) сверены построчно и
совпадают: blaze — только loot-таблица (2.5 % со снежного голема), скелет — пустыня
+ свет ≤ 7 + 0.7 %, визер — только добивающий удар Звездой Нечестивого + 13 %,
альфа-волк — добивающий удар Серебряным мечом + 10 %.

## 3.9. Проход «данные против генераторов»

Отдельная категория ошибок: правки жили в `tools/build_*.mjs`, а в репозитории
лежали **старые** `packs/` — и `npm run package` упаковывал именно их, потому что
сборка артефакта не вызывает `build:data`. Сверка «сгенерированное vs
закоммиченное» (112 файлов) плюс повторная генерация ничего не теряют —
генерация идемпотентна.

| Что | Было в `packs/` | Стало (генератор) |
|---|---|---|
| Торговля оружейника | ванильная 1.13: `trader_exp`/`max_uses` 16 вместо 6, порог 5-го тира 250 вместо 310 | полный набор 2.8.8 |
| `fake_ice` | `destroy_time 0.4`, `friction 0.02`, трение/яркость/цвет карты от ремейка | `9999`, `explosion_resistance 10`, `light_dampening 0` |
| `fireball` | хитбокс 1×1, `catch_fire: false`, выдуманный `impact_damage 6` | 0.31, `catch_fire: true`, только `definition_event` |
| `en_US`/`ru_RU` | страница Проклятой тыквы без строк, `lightblock2` потерян | как в генераторе |

## 3.10. Проход «типы урона и потерянные события сущностей»

| Находка | 2.8.8 | Было / стало |
|---|---|---|
| Причина урона `hot_floor` | такого типа в Bedrock нет (это Java) | триггер молча не срабатывал: Ультра Инстинкт, Эндермен, Огненный и Ифрит-мечи теряли иммунитет к лаве. Заменено на `lava` + `magma` |

| Пчелиный меч | яд даёт только вызванная пчела (`fatal_poison`, 3 с) | скрипт вешал `poison 80` на **каждое** попадание |
| `small_fireball` / `fireball` | `entity_spawned`: гравитация при выстреле игроком + `mob.ghast.fireball` на 12 (18 для Fire-меча) | событие и группы были выброшены — снаряды летели ровно и молча |

## 5. Что остаётся

Сценарный проход идёт волнами: каждый следующий проход по сценариям находит
меньше, но пока находит — см. 3.7. Работа считается законченной только после двух
подряд полных проходов без единой находки. Дополнительно не подтверждено и
требует очного прохода по `TESTING.md`:

- поведение в мультиплеере: питомцы, щиты, слизни, мечи времени при нестандартном `randomTickSpeed`;
- корректность на Android и Windows при одной версии игры.
